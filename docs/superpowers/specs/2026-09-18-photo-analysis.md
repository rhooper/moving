# Photo analysis in the background: rules and API contract

The contract the PWA is built against, pinned by `tests/test_api_analysis.py`
and `tests/test_analysis.py`; the implementation is `src/movingbox/analysis.py`.
Which models read a photo, and what they cost, is in `CLAUDE.md` ("Reading
photos").

## What the model may and may not change

Photo analysis *applies* what it finds (an on-demand `ai.draft_for_box` still
only proposes). What protects people's own work:

- Items the model adds are `source='ai'` and shown as *autogenerated*.
- A person's item is never renamed, re-counted or removed by the model.
- A summary a person typed is never overwritten: only an empty one, or one the
  model wrote (`boxes.summary_source = 'auto'`). A `PATCH` that sets
  `content_summary` marks it `manual`; clearing it hands it back.
- Renaming an autogenerated item makes it the person's (`source='manual'`).

## Behaviour

1. Uploading a photo to a record that holds contents queues one job for it. A
   single thing (loose item, furniture) queues nothing, and an upload that
   dedupes to an existing photo queues nothing new.
2. One worker thread runs jobs oldest-first, one at a time. Jobs live in
   `ai_jobs`; on startup, `running` jobs go back to `pending`. A re-run adds a
   row, and a photo's state is its latest row.
3. A finished job's result is stored on its row, then applied:
   - **Merge**: each item is matched against the record's items by normalised
     name (case, surrounding space, a trailing plural `s`/`es`). No match: added
     as `ai`. A match on an `ai` item: its quantity is raised if the new count
     is higher, never lowered. A match on a person's item: untouched.
   - **Summary**: if the summary is empty or `auto`, it is rebuilt from the
     record's whole subtree (`summarise.from_subtree`) and marked `auto`. With
     nothing to build from, the model's own sentence about the photo is used.
4. **Estimate**: the median `duration_ms` of the last 10 finished photo jobs
   for the same model, or 20,000 ms with no history. A queued photo's wait
   includes the jobs ahead of it.

## API

```
GET  /api/boxes/{code}/photos        (also the body of an upload's 201)
  each photo carries "srcset" (the strip image, see CLAUDE.md) and
  "analysis": null | {
      "status":       "pending" | "running" | "done" | "error",
      "remaining_ms": int,        # estimate from now; 0 when done or error
      "total_ms":     int,        # the whole expected span: the ring's fraction
                                  #   complete is 1 - remaining_ms / total_ms
      "items_found":  int | null, # done: how many items this photo showed
      "items":        [{"name": str, "qty": int}] | null,  # done: seen in THIS photo
      "summary":      str | null, # done: the model's sentence about this photo
      "detail":       bool,       # the closer look, not the quick read
      "provider":     str,        # who read it: written back when the job ends,
      "model":        str,        #   so the local fallback if it stepped in
      "error":        str | null
  }

POST /photos/{photo_id}/analyse[?detail=true]   -> 202, the photo as above
  Queue (or re-queue) one photo: a retry after an error, or a re-run.
  detail=true is the closer look; what it finds is merged in, never swapped in.
  404 unknown photo; 409 a single thing, which has no contents to list.

PATCH /api/items/{item_id}  {"name"?: str, "qty"?: int}   -> 200, the item
  Renaming an "ai" item makes it "manual". 404 unknown item; 422 empty name.
```

Events on `/api/events`, with no `origin` (no device caused them), so every
client acts on them:

- `photos.changed` (code): every job state change -- queued, started, done,
  failed.
- `items.changed` (code): a finished job added or re-counted items.
- `box.updated` (code): a finished job rewrote the autogenerated summary.

`MOVING_VISION_PROVIDER=stub` is a canned provider for UI work: it sleeps
`MOVING_VISION_STUB_SECONDS` (default 3) and returns a fixed draft.

## On the page

- Each photo shows a countdown ring from `remaining_ms` while pending or
  running; past zero and not done it turns indeterminate rather than sitting
  full. Done shows "N items found"; an error shows the message and Retry.
- The events above update the open record's items, photos and a pristine,
  unfocused summary in place, even while a whole-page refresh is held.
- Tapping an item's name edits it in place; Enter or blur saves through
  `PATCH /api/items/{id}`, Escape cancels.
